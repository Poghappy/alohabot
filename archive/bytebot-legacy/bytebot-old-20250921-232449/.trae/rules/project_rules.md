# 项目规则

## 项目概述

### ByteBot项目简介

ByteBot是一个基于AI的智能代理平台，旨在为用户提供高效的自动化解决方案。该项目采用微服务架构，包含多个核心组件：

- **bytebot-agent**: 核心AI代理服务，负责任务处理和智能决策
- **bytebot-agent-cc**: 客户端连接代理，处理客户端通信
- **bytebot-ui**: 用户界面组件，提供Web端交互体验
- **bytebotd**: 系统守护进程，负责计算机使用和输入跟踪
- **bytebot-llm-proxy**: LLM代理服务，处理大语言模型请求
- **shared**: 共享组件库，提供通用工具和类型定义

### 品牌替换项目目标

本项目的主要目标是将ByteBot平台的品牌标识系统从原有设计替换为Vincent品牌体系，具体包括：

#### 品牌替换范围
- **Logo替换**: 将所有ByteBot logo替换为Vincent品牌logo
- **图标更新**: 更新应用图标、favicon等品牌标识
- **UI元素**: 替换界面中的品牌相关视觉元素
- **文档更新**: 同步更新项目文档中的品牌信息

#### 技术实施要求
- **保持功能完整性**: 品牌替换不得影响现有功能
- **多端一致性**: 确保Web端、桌面端品牌显示一致
- **响应式适配**: 品牌元素在不同设备和分辨率下正确显示
- **性能优化**: 优化品牌资源文件大小和加载性能

#### 质量标准
- **视觉一致性**: 所有品牌元素符合Vincent品牌规范
- **技术规范**: 遵循项目现有的代码规范和文件组织结构
- **兼容性**: 确保品牌替换后的兼容性和稳定性
- **文档完整性**: 提供完整的品牌使用指南和技术文档

## 开发规范

### "不重复造轮子"原则标准化流程

在项目开发过程中，必须严格遵循"不重复造轮子"原则，按照以下标准化流程执行：

#### 1. 解决方案调研阶段
- **优先搜索平台**：优先在GitHub等开源平台进行全面搜索，寻找经过社区验证的成熟解决方案
- **搜索范围要求**：搜索范围应包括但不限于：
  * 功能匹配度评估
  * 技术栈兼容性分析
  * 性能指标对比
  * 社区活跃度调研
  * 维护状态评估

#### 2. 开源项目评估标准

##### 项目质量评估维度
- **项目活跃度**：
  * 提交频率（近6个月内的提交活跃度）
  * Issue响应速度（平均响应时间<7天）
  * PR处理效率（合并率>60%）
- **社区支持情况**：
  * Star数量（≥100为基础门槛）
  * Fork数量（活跃fork比例）
  * 贡献者数量（≥5个活跃贡献者）
  * 社区讨论活跃度
- **文档完整性**：
  * API文档完整性（覆盖率≥80%）
  * 使用示例丰富度
  * 部署指南清晰度
  * 故障排除文档
- **安全审计记录**：
  * 漏洞报告处理记录
  * 安全修复响应时间
  * 依赖安全扫描结果

##### 技术适配性评估维度
- **兼容性评估**：
  * 与现有技术栈的兼容性
  * 版本依赖冲突检查
  * 运行环境要求匹配
- **集成复杂度评估**：
  * 集成工作量估算
  * 配置复杂度分析
  * 学习成本评估
- **性能基准测试**：
  * 性能指标对比
  * 资源消耗评估
  * 扩展性验证

#### 3. 开发决策流程

##### 决策标准
- **采用现有方案条件**：
  * 功能匹配度≥80%
  * 质量评估总分≥4.0/5.0
  * 技术适配性评估通过
  * 维护成本可接受

- **自行开发触发条件**：
  * 经过全面评估确认没有合适的现有解决方案
  * 现有方案功能匹配度<60%
  * 集成成本超过自研成本
  * 特殊业务需求无法满足

##### 审批流程
- **自行开发方案审批**：
  * 技术可行性评审（解决方案架构师主导）
  * 资源投入评估（项目管理Agent评估）
  * 风险评估报告（质检Agent审核）
  * 技术负责人最终审批

#### 4. 项目维护规范

##### 集成维护要求
- **升级策略**：
  * 升级或重构时必须选择最简单的集成方式
  * 遵循渐进式升级原则
  * 保持向后兼容性
- **设计原则**：
  * 严格避免过度设计
  * 遵循KISS原则（Keep It Simple, Stupid）
  * 优先选择成熟稳定的方案
- **同步更新**：
  * 保持与上游项目的同步更新
  * 定期检查依赖版本更新
  * 及时应用安全补丁

##### 监控与优化
- **性能监控**：持续监控集成方案的性能表现
- **问题跟踪**：建立问题反馈和处理机制
- **优化迭代**：基于使用反馈持续优化集成方案

#### 5. 合规性要求

##### 开源方案合规检查
所有采用的开源方案必须满足以下要求：
- **技术合规**：
  * 符合项目技术栈要求
  * 满足性能和安全标准
  * 通过兼容性测试
- **业务合规**：
  * 满足具体业务需求
  * 符合功能性要求
  * 满足非功能性要求
- **法律合规**：
  * 遵守相关开源协议（MIT、Apache、GPL等）
  * 无知识产权冲突
  * 符合企业合规政策

##### 合规审查流程
- **技术审查**：开发Agent和架构师联合审查
- **法律审查**：质检Agent进行合规性检查
- **业务审查**：需求分析Agent确认业务匹配度
- **最终审批**：发布Agent进行最终合规确认

#### 6. 敏捷团队协作执行

##### 角色分工
- **需求分析Agent**：负责业务需求匹配度评估
- **解决方案架构师**：负责技术方案评估和架构设计
- **开发Agent**：负责技术实现和集成开发
- **测试Agent**：负责集成测试和性能验证
- **质检Agent**：负责合规性检查和质量审核
- **发布Agent**：负责最终审批和发布决策

##### 协作流程
- **并行评估**：多个Agent同时进行不同维度的评估
- **定期同步**：每日站会同步评估进展和发现的问题
- **决策会议**：重要决策通过团队会议集体决定
- **文档记录**：所有评估过程和决策结果必须文档化

##### 质量保证
- **双重审查**：关键决策必须经过至少两个Agent的独立审查
- **可追溯性**：所有决策过程必须可追溯和可审计
- **持续改进**：定期回顾和优化评估标准和流程

**注**：执行过程中需以专业Agent团队的多角色协作模式运作，确保每个环节都符合正规项目流程标准，所有决策都经过充分的技术评估和团队协作。
### 代码质量标准
- 遵循代码可读性、可维护性和安全性原则
- 重要功能必须有相应的文档说明
- 基于官方源码分析，不得猜想或推测未实现功能
- 找不到答案时直接汇报"暂无结果"

### 文件路径规范
- 使用相对于项目根目录的完整文件路径
- 引用文件时使用格式："src/.trae/rules/templates.md"

## MCP工具使用规范

### 核心原则
- **MCP优先原则**：所有外部工具操作必须通过MCP接口执行
- **工具适配原则**：根据任务特性选择最适合的MCP工具
- **配置验证原则**：执行前必须验证MCP工具配置状态
- **故障处理原则**：MCP工具故障时必须完整解决后再继续任务

### 工具分类与优先级

#### 浏览器自动化类
- **优先级排序**：playwright > puppeteer > selenium-based
- **适用场景**：网页操作、UI测试、表单填写、页面截图
- **技术要求**：支持现代浏览器API、具备稳定性保证

#### 网页抓取类
- **优先级排序**：firecrawl > scrapy-based > requests-based
- **适用场景**：内容提取、数据抓取、文档处理、API调用
- **技术要求**：支持多种数据格式、具备反爬虫能力

#### 容器管理类
- **优先级排序**：Docker MCP > kubernetes-mcp > podman-mcp
- **适用场景**：容器创建、启动、停止、删除、镜像管理
- **技术要求**：支持完整Docker API、具备安全隔离

#### 云服务集成类
- **选择标准**：根据具体云服务提供商选择对应MCP工具
- **安全要求**：必须支持安全认证机制（OAuth、API Key等）
- **性能要求**：支持批量操作和异步处理

#### 数据库操作类
- **选择标准**：根据数据库类型（MySQL、PostgreSQL、MongoDB等）选择
- **兼容性要求**：支持主流数据库协议和连接池
- **安全要求**：支持加密连接和事务管理

### MCP工具选择流程

#### 1. 需求分析阶段
- **任务类型识别**：明确任务属于哪个工具分类
- **功能需求评估**：列出具体的功能要求和性能指标
- **技术约束分析**：评估现有技术栈的兼容性要求
- **安全要求确认**：确定安全级别和合规要求

#### 2. 工具评估阶段
- **候选工具筛选**：基于分类优先级筛选候选工具
- **功能匹配度评估**：评估工具功能与需求的匹配程度
- **技术适配性评估**：验证与现有系统的集成复杂度
- **性能基准测试**：对比不同工具的性能表现

#### 3. 配置验证阶段
- **配置状态检查**：验证所选MCP工具是否已正确配置
- **连接测试**：测试MCP工具与目标系统的连接状态
- **权限验证**：确认工具具备执行任务所需的权限
- **功能验证**：执行简单测试确保工具功能正常

#### 4. 执行决策阶段
- **最终工具确定**：基于评估结果确定使用的MCP工具
- **配置优化**：根据任务需求优化工具配置参数
- **监控设置**：配置工具执行过程的监控和日志
- **异常处理**：制定工具执行失败的应对策略

### 配置管理规范

#### 配置文件管理
- **配置文件位置**：统一存放在`.mcp/config/`目录下
- **配置文件格式**：使用YAML格式，支持环境变量替换
- **版本控制**：配置文件纳入版本控制，敏感信息使用环境变量
- **配置验证**：提供配置文件格式验证和完整性检查

#### 环境变量管理
- **命名规范**：使用`MCP_<TOOL_NAME>_<PARAM_NAME>`格式
- **敏感信息**：API密钥、密码等敏感信息必须使用环境变量
- **默认值设置**：为非敏感配置项提供合理的默认值
- **文档说明**：为每个环境变量提供详细的说明文档

#### 配置热更新
- **支持范围**：非关键配置项支持热更新
- **更新机制**：通过配置文件变更触发自动重载
- **验证机制**：更新前进行配置有效性验证
- **回滚机制**：配置更新失败时自动回滚到上一版本

### 故障处理与恢复

#### 故障检测机制
- **健康检查**：定期执行MCP工具健康状态检查
- **连接监控**：实时监控工具与目标系统的连接状态
- **性能监控**：监控工具执行性能，及时发现性能异常
- **日志分析**：通过日志分析识别潜在问题和异常模式

#### 故障分类与处理

##### 配置错误类故障
- **故障特征**：工具无法启动或连接失败
- **处理流程**：
  1. 检查配置文件语法和完整性
  2. 验证环境变量设置
  3. 确认目标系统可访问性
  4. 重新加载配置并测试

##### 权限不足类故障
- **故障特征**：工具可连接但操作被拒绝
- **处理流程**：
  1. 检查API密钥或认证信息
  2. 验证用户权限和角色设置
  3. 确认目标资源的访问权限
  4. 更新权限配置并重试

##### 网络连接类故障
- **故障特征**：连接超时或网络不可达
- **处理流程**：
  1. 检查网络连接状态
  2. 验证防火墙和代理设置
  3. 测试目标服务可用性
  4. 调整超时和重试参数

##### 资源限制类故障
- **故障特征**：内存不足或并发限制
- **处理流程**：
  1. 检查系统资源使用情况
  2. 调整工具并发和内存参数
  3. 优化任务执行策略
  4. 考虑资源扩容或任务分片

#### 恢复策略

##### 自动恢复机制
- **重试策略**：指数退避重试，最大重试次数限制
- **熔断机制**：连续失败达到阈值时暂停服务
- **降级策略**：关键功能不可用时启用备用方案
- **自愈能力**：自动检测并修复常见配置问题

##### 手动恢复流程
- **问题诊断**：收集错误日志和系统状态信息
- **根因分析**：分析故障根本原因和影响范围
- **修复执行**：按照标准流程执行修复操作
- **验证测试**：修复后进行功能验证和回归测试

### 性能优化规范

#### 连接池管理
- **连接复用**：使用连接池避免频繁建立连接
- **池大小配置**：根据并发需求合理配置连接池大小
- **连接超时**：设置合理的连接和读取超时时间
- **连接监控**：监控连接池使用情况和性能指标

#### 缓存策略
- **结果缓存**：对重复查询结果进行缓存
- **配置缓存**：缓存配置信息减少重复读取
- **连接缓存**：缓存认证信息和连接状态
- **缓存失效**：设置合理的缓存过期时间和失效策略

#### 并发控制
- **并发限制**：设置合理的并发执行数量限制
- **队列管理**：使用队列管理待执行任务
- **负载均衡**：在多个工具实例间分配负载
- **资源隔离**：避免不同任务间的资源竞争

### 安全规范

#### 认证与授权
- **身份认证**：支持多种认证方式（API Key、OAuth、JWT等）
- **权限控制**：实施最小权限原则，仅授予必要权限
- **令牌管理**：安全存储和定期轮换访问令牌
- **审计日志**：记录所有认证和授权操作

#### 数据安全
- **传输加密**：使用HTTPS/TLS加密数据传输
- **存储加密**：敏感数据存储时进行加密
- **数据脱敏**：日志中的敏感信息进行脱敏处理
- **数据清理**：及时清理临时文件和缓存数据

#### 网络安全
- **访问控制**：限制MCP工具的网络访问范围
- **防火墙配置**：配置防火墙规则限制不必要的网络连接
- **代理支持**：支持通过代理服务器访问外部资源
- **SSL证书验证**：严格验证SSL证书有效性

### 监控与日志

#### 监控指标
- **可用性监控**：监控MCP工具的可用性和响应时间
- **性能监控**：监控执行时间、吞吐量、错误率等指标
- **资源监控**：监控CPU、内存、网络等资源使用情况
- **业务监控**：监控任务执行成功率和业务指标

#### 日志管理
- **日志级别**：支持DEBUG、INFO、WARN、ERROR等日志级别
- **日志格式**：使用结构化日志格式（JSON）便于分析
- **日志轮转**：配置日志文件大小和保留策略
- **日志聚合**：将分布式日志聚合到中央日志系统

#### 告警机制
- **阈值告警**：基于监控指标设置告警阈值
- **异常告警**：检测到异常模式时触发告警
- **告警通知**：支持邮件、短信、钉钉等多种通知方式
- **告警抑制**：避免重复告警和告警风暴

```python
def should_trigger_auto_generation(user_input: str, conversation_history: List[str]) -> bool:
    """
    综合判断是否触发自动生成
    
    Args:
        user_input: 当前用户输入
        conversation_history: 对话历史记录
    
    Returns:
        bool: 是否触发自动生成
    """
    total_score = 0.0
    
    # 1. 关键词检测
    keywords = ["牛逼", "很好", "确认", "认可", "同意", "采用", "通过", "OK", "好的"]
    for keyword in keywords:
        if keyword in user_input:
            total_score += 1.0
            break  # 只计算一次关键词分数
    
    # 2. 模式匹配
    patterns = [
        r"确认.*需求", r"认可.*方案", r"同意.*设计", 
        r"采用.*建议", r"通过.*评审", r"接受.*提案", r"批准.*计划"
    ]
    for pattern in patterns:
        if re.search(pattern, user_input):
            total_score += 1.5
            break  # 只计算一次模式分数
    
    # 3. 上下文验证
    context_keywords = ["需求文档", "用户故事", "技术方案", "设计文档", "项目计划"]
    recent_context = " ".join(conversation_history[-5:])  # 最近5条记录
    for ctx_keyword in context_keywords:
        if ctx_keyword in recent_context:
            total_score += 0.8
            break  # 只计算一次上下文分数
    
    # 触发阈值：总分 >= 1.5
    return total_score >= 1.5
```
