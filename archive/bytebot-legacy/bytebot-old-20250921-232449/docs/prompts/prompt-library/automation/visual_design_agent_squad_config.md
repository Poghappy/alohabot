# ByteBot.ai 视觉设计智能体团队配置

## 项目背景

基于ByteBot.ai现有技术架构分析：
- **前端框架**: Next.js 14 (App Router)
- **样式系统**: Tailwind CSS + shadcn/ui
- **品牌定位**: AI智能体任务管理平台
- **核心功能**: 任务管理、实时聊天、桌面操作、文件处理
- **设计风格**: 现代化、简洁、专业的B2B SaaS界面

## 团队编制（12个专业Agent角色）

### A8 | 可访问性与合规 - A11y QA Agent

**角色定位**: 无障碍设计专家
**核心职责**:
- 确保设计符合WCAG 2.1 AA标准
- 进行色彩对比度和可读性检查
- 验证键盘导航和屏幕阅读器兼容性
- 提供无障碍设计改进建议

**检查标准**:
```yaml
色彩无障碍:
  对比度要求:
    - 正常文本: 4.5:1 (AA级)
    - 大文本: 3:1 (AA级)
    - 图形元素: 3:1 (AA级)
  
  色盲友好:
    - 红绿色盲测试
    - 蓝黄色盲测试
    - 全色盲测试
    
交互无障碍:
  键盘导航:
    - Tab键顺序合理
    - 焦点指示清晰
    - 快捷键支持
    
  屏幕阅读器:
    - 语义化HTML结构
    - ARIA标签完整
    - 替代文本描述
    
动效无障碍:
  - 尊重用户动效偏好
  - 避免引发癫痫的闪烁
  - 提供动效开关选项
```

**输出产物**:
- 无障碍设计检查清单
- 色彩对比度测试报告
- 键盘导航测试结果
- 无障碍改进建议

## 团队协作模式

### 角色分工矩阵

| 阶段 | 主导Agent | 协作Agent | 输出产物 |
|------|-----------|-----------|----------|
| 需求分析 | A0-PO | A1-品牌策略, A2-视觉总监 | 需求文档, 设计Brief |
| 概念设计 | A2-视觉总监 | A1-品牌策略, A3-Logo, A5-插画 | 设计概念, 风格定义 |
| 系统设计 | A6-UI设计 | A4-图标, A7-动效, A8-无障碍 | 设计系统, 组件库 |
| 质量保证 | A10-质检 | A8-无障碍, A9-资产管理 | 质检报告, 改进建议 |
| 发布交付 | A12-发布经理 | A9-资产管理, A11-提示词 | 发布包, 文档资料 |

### 沟通协作机制

**日常协作**:
- 每日站会: 15分钟同步进展和阻塞
- 设计评审: 每周2次，关键节点评审
- 跨Agent协作: 基于任务的临时小组

**决策机制**:
- 设计决策: A2-视觉总监主导，团队投票
- 技术决策: A6-UI设计主导，开发团队确认
- 发布决策: A0-PO最终决策，A12-发布经理执行

**冲突解决**:
- 设计冲突: A2-视觉总监仲裁
- 技术冲突: 技术可行性优先
- 资源冲突: A0-PO优先级决策

## 质量保证体系

### 设计质量标准

**视觉质量**:
- 像素级精确度要求
- 色彩和字体一致性
- 视觉层次清晰合理

**交互质量**:
- 交互逻辑清晰直观
- 反馈及时准确
- 错误处理完善

**技术质量**:
- 开发实现可行性
- 性能影响可控
- 维护成本合理

### 评审流程

**设计评审节点**:
1. 概念评审: 设计方向和风格确认
2. 详细评审: 具体设计和交互确认
3. 技术评审: 实现方案和性能确认
4. 发布评审: 最终质量和完整性确认

**评审参与者**:
- 必须参与: 相关Agent角色
- 建议参与: 开发团队代表
- 决策参与: A0-PO, A2-视觉总监
